# Physics Model Integration (FMU)

## Overview
PowerSimBuilder imports Co-Simulation FMUs as first-class components.
Each `.fmu` becomes a single Component (`ComponentKind.Physics`).

## Get an FMU (China-accessible sources)
| Site | URL pattern | Access from CN |
|------|-------------|----------------|
| MoHub | mohub.net -> .fmu | Yes (domestic) |
| Gitee | gitee.com -> ZIP | Yes (domestic) |
| PyPI (Tsinghua mirror) | pypi.tuna.tsinghua.edu.cn -> fmpy wheel | Yes (domestic) |
| FMI Reference FMUs | github.com -> .fmu | Slow, use gh-proxy.com |
| OpenModelica | openmodelica.org -> build .fmu | Slow, use Docker image |

## Install fmpy
```powershell
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
pip install fmpy
python -c "import fmpy; print(fmpy.__version__)"
```

## Import
Toolbar -> **Import Physics Model** -> select `.fmu` -> check ports ->
**Import**. Files land in `user_physics_models/<name>/`.

## FMU Parsing
- The FMU is opened as a ZIP archive, and the internal `modelDescription.xml` is read directly.
- The entire FMU is not extracted.
- Variables selectable in the UI are limited to those with a `causality` of `input` or `output`.
- At least one variable must be selected to execute the import.

## File Structure After Import
Imported models are saved with the following structure:

```text
user_physics_models/<model-name>/
├── model.yaml
├── README.md
└── source/
    └── <original-fmu-file>.fmu
```

- The original FMU file is copied into `source/`.
- `model.yaml` is generated.
- `README.md` is generated only if it does not already exist. An existing `README.md` is never overwritten.
- `usage_example.py` is **not** generated by the normal import process. The Python usage example is shown on the import-success screen.

## Save Location

- If the current directory contains `.git` or `PowerSimBuilder.csproj`: `<current-directory>/user_physics_models`
- Otherwise: `<application-directory>/user_physics_models` (`AppContext.BaseDirectory`)

## Generated `model.yaml`

```yaml
name: <model-name>
source:
  type: fmu
  file: source/<original-fmu-file>
interface:
  fmi_type: <FMI-type>
  inputs:
    <selected-input>: <same>
  outputs:
    <selected-output>: <same>
  parameters: {}
units: {}
timing:
  mode: fixed_step
  dt_internal: 0.001
```

- `parameters` and `units` are empty in the initially generated file.
- Selected ports are written as `fmu_port: component_port`; initially both names are identical.

## Model Registration

Models are discovered from `user_physics_models/`: each model folder must contain a `model.yaml` directly inside it. Deeper nested folders are not scanned recursively.

## `.mo` (Modelica source) is **not** accepted
If you have a `.mo`, build an FMU first:
```powershell
docker run --rm -v ${PWD}:/work openmodelica/openmodelica:v1.22.0-omc `
  omc -s /work/MyModel.mo /work/build.mos
```
Then import the resulting `.fmu`.

## Runtime
- `FmuAdapter` wraps one Co-Simulation FMU.
- `step(dt)` calls `doStep(currentCommunicationPoint, dt)`.
- Only FMI 2.0/3.0 Co-Simulation is supported in MVP-1.

See [FMU Catalog and Import Guide](FMU_CATALOG_GUIDE.md) for the Catalog / URL / File workflow.
